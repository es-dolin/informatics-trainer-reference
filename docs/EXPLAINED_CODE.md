# Как устроен код тренажёра

Этот разбор показывает путь от нажатия кнопки до проверенного ответа. Главная идея проекта — отделять вычисления от страницы: модули решают задачи, а `app.js` показывает их пользователю.

## 1. HTML подключает страницу и программу

В `index.html` важны три строки:

```html
<div class="app-shell" id="app">Загружаем тренажёр…</div>
<link rel="stylesheet" href="./css/styles.css">
<script type="module" src="./js/app.js"></script>
```

`id="app"` — место, которое JavaScript заполнит интерфейсом. `href` и `src` начинаются с `./`: это относительные пути, поэтому они работают и в подпапке GitHub Pages. Атрибут `type="module"` включает систему `import`/`export` браузера.

## 2. Объект задания — договор между модулем и страницей

Генератор возвращает обычный объект JavaScript. Упрощённо:

```js
{
  prompt: "Переведи число…",
  input: { type: "text", label: "Твой ответ" },
  answer: "1010",
  hint: "Собери остатки снизу вверх.",
  steps: ["Первый шаг…", "Следующий шаг…"]
}
```

`prompt` — формулировка, `input.type` подсказывает интерфейсу, какое поле создать, `answer` хранит правильный результат, `hint` и `steps` нужны для обучения. В дополнительных свойствах `meta` лежат числа, из которых получилась задача. Они помогают функции проверки пересчитать ответ независимо.

## 3. Генерация и перевод числа

В `systems.js` функция `fromDecimal(number, base)` выполняет перевод делением с остатком:

```js
const quotient = Math.floor(current / base);
const remainder = current % base;
remainders.push(DIGITS[remainder]);
current = quotient;
```

`%` — остаток от деления, а `Math.floor` округляет частное вниз. Остаток становится очередной цифрой нового числа. Последний остаток — старший разряд, поэтому массив остатков в конце переворачивается через `reverse()`.

Ноль обрабатывается отдельно: цикл деления для него не запустился бы, а запись нуля всё равно нужна.

Функция `toDecimal(text, base)` идёт в другую сторону. Она проверяет каждую цифру и накапливает значение по правилу `новое значение = старое значение × основание + цифра`. Если, например, в двоичной записи встретилась цифра 2, функция выдаёт ошибку вместо неправильного результата.

`generateConversionTask()` выбирает значение от 0 до 1024, исходное и целевое основания. Получившееся задание сразу сохраняет правильный ответ и обе стороны перевода. Поэтому проверка может независимо убедиться, что исходная и итоговая записи обозначают одно число.

### Сравнение и знак равенства

`generateComparisonTask()` сначала случайно выбирает один из трёх случаев: меньше, равно или больше. Для равенства левая и правая стороны получают одно десятичное значение, но записываются в разных основаниях. Для знака < генератор строит правое значение больше левого; для > — левое больше правого. Основания выбираются отдельно и всегда отличаются.

Правильный знак определяется сравнением числовых значений `leftValue` и `rightValue`, а не сравнением текстовых строк. Например, запись «10» в основании 2 меньше «7» в основании 8: эти числа означают 2 и 7. Тесты создают все три знака и проверяют значения обратным переводом через `toDecimal()`.

### Генератор для пошагового урока

`generateGuidedConversionTask()` создаёт число от 12 до 255 и выбирает новое основание 2, 8 или 16. Затем цикл делит текущее число, пока частное не станет нулём:

```js
const quotient = Math.floor(current / targetBase);
const remainder = current % targetBase;
divisions.push({ dividend: current, quotient, remainder: DIGITS[remainder] });
current = quotient;
```

Одна запись `divisions` хранит делимое, частное и остаток. Для каждого деления верно равенство «делимое = частное × основание + остаток», а остаток находится от 0 до основания − 1. Поэтому приложение знает ответ каждого шага и может проверить ученика.

Когда цикл заканчивается, остатки соединяются в обратном порядке. Первый остаток относится к младшему разряду, последний — к старшему. Функция `fromDecimal()` строит итоговый ответ тем же математическим способом.

## 4. Переносы и заимствования в арифметике

В `arithmetic.js` функции `addColumnSteps()` и `subtractColumnSteps()` выравнивают записи по правому краю с помощью `padStart()`, а затем идут справа налево.

При сложении к цифрам столбца добавляется перенос из предыдущего разряда. Остаток от деления на основание становится цифрой результата, а целая часть — новым переносом. Поэтому тот же алгоритм работает для основания 2, 8 и 16.

При вычитании переменная `borrow` означает, что из следующего старшего разряда уже заняли единицу. Если верхняя цифра меньше нижней, к ней прибавляется основание. В двоичной системе это добавляет 2, в восьмеричной — 8.

Умножение раскладывается на частичные произведения: каждый разряд множителя равен нулю или единице. В двоичном делении генератор сначала выбирает делитель и целое частное, а затем строит делимое их произведением. Это исключает неоднозначность остатка в тренировочном поле.

## 5. Безопасные логические выражения

`logic.js` хранит выражение не в виде строки для исполнения, а как дерево объектов:

```js
{ type: "and", left: variable("A"), right: not(variable("B")) }
```

Функция `evaluateExpression()` смотрит на `type`. Для `variable` она возвращает значение переменной, для `not` меняет его, а для `and` и `or` рекурсивно считает левую и правую части.

Рекурсия — это когда функция вызывает сама себя для частей задачи. Здесь выражение небольшое и создаётся приложением заранее, поэтому глубина всегда ограничена.

`buildTruthTable(expression, variables)` перебирает числа от 0 до `2ⁿ−1`. Их двоичные разряды становятся значениями переменных. Для трёх переменных получается восемь строк: от `000` до `111`. Каждая строка проходит через тот же `evaluateExpression()`.

## 6. Состояние исполнителя и след

В `executors.js` команда хранится как числа, например `{ dx: 2, dy: -1 }`. `computeDrawing()` берёт текущую точку, прибавляет смещение и записывает новую точку в массив. Для повторения блок заранее разворачивается в конечную последовательность команд.

Путь отрисовывается как SVG-ломаная. Координаты точек переводятся в экранные координаты: ось Y инвертируется, потому что в SVG начало находится вверху. Для расчёта ответа используются исходные целые координаты, а не пиксели рисунка.

Числовой исполнитель `simulateNumberCommands()` принимает только строку команд из цифр 1 и 2. Он не исполняет JavaScript и не принимает другие команды. После каждого шага добавляет новое значение в список, чтобы его можно было объяснить.

## 7. Симуляция фиксированной программы

В `programs.js` примеры кода создаются из заранее известных шаблонов. Для программы с условием функция `simulateCondition()` отдельно сравнивает первое и второе условие и возвращает `YES` или `NO`. Функция `makeConditionTask()` заранее применяет эти сравнения к пяти парам чисел и строит список правильных номеров.

В шаблоне цикла числа берутся из массива. На каждом повторе выполняется одна фиксированная операция сложения. `trace` сохраняет промежуточное значение, поэтому сайт показывает, как меняется сумма.

В поле ответа принимаются только номера вариантов либо число результата. Текст программы из поля ответа нигде не исполняется.

## 8. HTML и обработчики событий

`app.js` создаёт разметку строками и записывает её в контейнер `#app`. Функция `escapeHtml()` заменяет специальные символы в тексте задания на безопасные HTML-обозначения перед вставкой.

Вместо отдельного обработчика на каждую кнопку приложение использует делегирование событий:

```js
app.addEventListener("click", (event) => {
  const target = event.target.closest("[data-action], [data-module], [data-mode]");
  // выбираем действие по атрибуту кнопки
});
```

Событие всплывает от нажатого элемента к контейнеру. `closest()` находит кнопку с нужным `data-*` атрибутом. Так все экраны используют один обработчик.

Форма ответа слушает событие `submit`, отменяет перезагрузку страницы через `preventDefault()`, собирает значения элементов и вызывает `checkAnswer()` выбранного модуля. Для таблицы истины ответы собираются из всех `<select>`, для множественного выбора — из отмеченных флажков.

## 9. Режимы обучения

Состояние интерфейса хранится в объекте `state`: текущий экран, модуль, режим, задание, видимость подсказки и обратная связь.

- `study` показывает теорию и раскрываемый пример. В модуле систем счисления вместо обычного поля ответа появляется интерактивный перевод: ученик вводит частное и остаток, а затем собирает число.
- `practice` позволяет открыть подсказку кнопкой.
- `test` не показывает подсказку до отправки ответа.

Переключение режима не вызывает `refreshTasks()`. Перед перерисовкой `saveVisibleAnswer()` сохраняет содержимое поля и незавершённый шаг урока. `renderInput()` восстанавливает текст, выбранные переключатели и значения таблицы. Подсказка прячется при выходе из «Практики». Кнопка «Новое задание» намеренно очищает ответы и запускает генератор.

## 10. Первая попытка и статистика

Флаг `state.attemptRecorded` относится к текущей сгенерированной задаче. `refreshTasks()` устанавливает его в `false`. Пустой ответ не записывается. При первом непустом ответе `shouldCountAnswer()` возвращает `true`: `recordAttempt()` сохраняет результат, а флаг переключается в `true`.

Ученик может исправить ответ и отправить его ещё раз. Приложение покажет новый результат, но попытка уже учтена, поэтому повторная проверка не меняет `localStorage`. Сообщение под результатом объясняет это правило. Новое задание сбрасывает флаг и начинает следующую попытку.

## 11. Локальный прогресс

`storage.js` хранит только количество попыток и верных ответов по пяти темам. `JSON.stringify()` превращает объект в строку, `JSON.parse()` восстанавливает объект при загрузке.

Чтение, разбор и запись обёрнуты в `try/catch`. Это нужно, если хранилище выключено, строка повреждена или браузер запретил доступ. `safeCount()` заменяет отрицательные и нецелые значения на ноль, чтобы испорченная статистика не ломала экран.

## 12. Тесты и локальный сервер

Файлы `tests/*.test.js` используют встроенный модуль `node:test`. Они проверяют вычисления, граничные случаи, все три знака сравнения, шаги перевода, правило первой попытки, хранилище и пользовательские сценарии пяти модулей. `tests/app.test.js` использует простой макет DOM, чтобы проверить обработчики без браузера. Фиксированные случайные числа делают сценарии повторяемыми.

`tools/dev-server.js` использует стандартный модуль `node:http`, отдаёт HTML, CSS и JavaScript из публичных папок и блокирует запросы к другим файлам проекта. Сборки, сервера приложения и сторонних пакетов нет.
