# Карта проекта

## Папки и файлы

| Путь | Назначение |
|---|---|
| `index.html` | Начальная HTML-страница, подключает стили и точку входа JavaScript. |
| `css/styles.css` | Цвета, сетки, карточки, состояния заданий, адаптивная раскладка и анимации. |
| `js/app.js` | Показывает экраны, учебные шаги и их историю, принимает промежуточные и итоговые ответы, сохраняет их при смене режима. |
| `js/learning-steps.js` | Строит учебные маршруты всех существующих типов задач и проверяет ответы на промежуточные вопросы. |
| `js/similar-task.js` | Описывает доступные виды заданий и создаёт новое задание на тот же приём: сохраняет подтип, основания и арифметическую операцию, меняет исходные данные. |
| `js/storage.js` | Читает и сохраняет обезличенные счётчики в `localStorage`; решает, можно ли засчитать первую попытку; переживает повреждённую запись. |
| `js/modules/index.js` | Список пяти модулей и их связь с общими экранами. |
| `js/modules/systems.js` | Перевод чисел, пошаговые деления для режима разбора и сравнение записей со знаками `<`, `=` и `>`. |
| `js/modules/arithmetic.js` | Арифметика в основаниях 2, 8 и 16. |
| `js/modules/logic.js` | Дерево логического выражения, вычисление и построение таблиц истинности. |
| `js/modules/executors.js` | Числовой исполнитель и координатный «Чертёжник». |
| `js/modules/programs.js` | Фиксированные шаблоны программ и их безопасная пошаговая симуляция. |
| `tools/dev-server.js` | Маленький локальный HTTP-сервер на стандартном модуле Node.js. |
| `tools/browser-check.js` | Проверяет интерфейс в настоящем Edge/Chrome в отдельном профиле, сохраняет скриншоты в `artifacts/browser`. |
| `tests/` | Автоматические тесты модулей, localStorage и DOM-сценариев всех пяти тем. |
| `docs/` | Матрица ВПР, карта, объяснения кода, мост Python–JavaScript и тест-план. |
| `package.json` | Команды `npm run dev`, `npm test` и `npm run test:browser`; внешних зависимостей нет. |

## Как проходит ответ

1. `app.js` выбирает объект модуля из `modules/index.js`.
2. Функция `generateTask()` создаёт учебное упражнение. Для перехода к самостоятельному решению `generateSimilarTask()` подбирает новую задачу на тот же приём.
3. `app.js` отображает поля по типу (`text`, `choice`, `multi-choice` или `truth-table`).
4. После отправки итогового ответа в «Проверь себя» приложение вызывает `checkAnswer()` этого же модуля. Учебные шаги проверяются отдельно.
5. Чистая функция возвращает результат проверки и понятное сообщение; приложение показывает обратную связь и шаги решения.
6. `shouldCountAnswer()` разрешает учесть только первый непустой итоговый ответ самостоятельной задачи. `recordAttempt()` сохраняет его в `localStorage`; учебные шаги и повторные проверки счётчики не меняют.
7. При смене режима `saveVisibleAnswer()` сохраняет введённые данные. Учебный маршрут и самостоятельный ответ запоминаются отдельно. Новая самостоятельная задача начинает следующую попытку.

## Начальный пример систем счисления

`generateGuidedConversionTask()` создаёт стартовый пример: десятичное число от 12 до 255, основание 2, 8 или 16 и список верных делений. Дальше он передаётся в тот же `createLearningSteps()`, что и задания остальных тем. Перевод десятичного числа в десятичное значение не требует отдельного вопроса, поэтому ученик сразу вводит частное и остаток. После всех делений он собирает цифры снизу вверх.

Задача учебного разбора не входит в статистику ответов. Новые записи в счётчиках относятся только к самостоятельным ответам в «Проверь себя». Ранее сохранённые результаты не сбрасываются.

## Общий пошаговый маршрут

`createLearningSteps(task)` возвращает массив вопросов. Каждый вопрос содержит `group`, `title`, `prompt`, `fields`, `hint` и `explanation`. В полях описаны допустимые варианты либо основание числа. `studyTask` хранит учебный пример, а `studyGuide` его текущий индекс, черновик и историю. Самостоятельное задание хранится отдельно в `task`. `checkLearningStep()` проверяет все поля шага, а `submitLearningStep()` переводит на следующий только после правильного ответа. Эти проверки не вызывают `recordAttempt()`.

В «Изучай и тренируйся» слева показаны действия текущего шага, справа - инструкция и нужное правило; на узком экране инструкция переносится внутрь задания. «Ещё пример» меняет данные, сохраняя изучаемый приём. Выбор задания связан с `taskVariants`, `getTaskVariant()` и `generateTaskForVariant()`. Для перевода отдельно выбираются исходное и новое основание; смена незавершённого решения требует подтверждения.

В «Проверь себя» помощь не отрисовывается до ответа. Обычная смена режима сохраняет черновик самостоятельной задачи. После непустой попытки «Решить по шагам» открывает именно эту задачу в `studyTask`; ссылка на неё сохраняется в `reviewedTestTask`. «Показать готовое решение» раскрывает текст готового разбора. Следующая самопроверка создаёт новую аналогичную задачу. Разбор не добавляет попытку и не переписывает предыдущий результат. Для очистки результатов нужно подтверждение.

Математические функции не знают о HTML. Поэтому их можно проверять Node.js тестами и повторно использовать при развитии интерфейса.
